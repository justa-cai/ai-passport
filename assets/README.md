# Assets

This directory stores reusable fonts, images, music, sound effects, and battery profiles, organized by asset type.

Keep each asset in the matching subdirectory and document its destination, naming, integration method, and source/license. Do not mix binary assets with Markdown documentation.

## Fonts

Store reusable font files and generated font sources in `fonts/`.

- Use descriptive names that include the family, weight, size, and format when relevant.
- Document the source, license, character range, conversion command, and expected destination.
- Check Flash and internal-RAM impact before adding a font; the ESP32-C3 has no PSRAM.
- Do not commit fonts whose license does not permit redistribution.

### Pinyin application font subsets (branch `feature/pinyin-cards`)

| File | Content and provenance |
| --- | --- |
| [`fonts/pinyin_charset.txt`](fonts/pinyin_charset.txt) | Character inventory (403 code points): every string literal in `main/*.[ch]` (NFC) union ASCII, the 36 precomposed tone-marked vowels plus `ü`, and UI symbols. Acts as both generator output and coverage-gate input. |
| `fonts/pinyin_font_16.c` / `pinyin_font_22.c` / `pinyin_font_44.c` | Full-inventory subsets at 16 px (Regular), 22 px (Medium), 44 px (Medium) for hints, body text, and quiz hanzi/stars. |
| `fonts/pinyin_font_56.c` | 133-code-point Latin subset (ASCII + tone-marked vowels + symbols) for large pinyin display; deliberately no fallback to avoid baseline mismatch. |

Source face: **Noto Sans CJK SC** (= Source Han Sans SC), SIL OFL 1.1, from
`/usr/share/fonts/opentype/noto/NotoSansCJK-{Regular,Medium}.ttc` on the build
machine; the `.ttc` files are not committed. Generated by the in-repo
rasterizer `tools/gen_app_fonts.py` (Pillow/FreeType direct emission with
per-pixel readback verification; `lv_font_conv` is not trusted on current
Node.js per `docs/reference/shinku-chen/lvgl-cjk-font-subsets.md`). Regenerate
with `python3 tools/gen_app_fonts.py`; the gate runs
`tests/test_font_coverage.py` against the committed inventory. cmaps use
`FORMAT0_TINY` + `SPARSE_TINY` only. Combined bitmap payload ≈ 455 KB Flash;
runtime copies for the fallback chain live in static RAM.

## Music and sound effects

Store reusable music and sound-effect sources in `music/`.

- Document the source, license, sample rate, bit depth, channels, conversion command, and destination.
- Prefer 16 kHz, 16-bit mono PCM when it matches the current BSP audio path.
- Check Flash and internal-RAM cost before embedding audio; stream or chunk long recordings.
- Do not commit media without redistribution permission.

### Pinyin pronunciation clips (branch `feature/pinyin-cards`, under `audio/`)

| File | Content and provenance |
| --- | --- |
| [`audio/pinyin_audio_ima.bin`](audio/pinyin_audio_ima.bin) | 255 clips, IMA-ADPCM 4-bit at 16 kHz mono (per-clip 4-byte header, contiguous nibbles low-first), 4-byte aligned offsets: 24 finals × 4 tones + 23 initial call-readings + 16 whole-syllables × 4 tones (174 unique core ids) + the 81-clip example-word pool. |
| [`audio/pinyin_audio_manifest.json`](audio/pinyin_audio_manifest.json) | Per-clip id, source (`voc:*` / `tts`), TTS text, raw/trimmed durations, voice, and generator date. |

Two sources, chosen per clip by `tools/gen_pinyin_audio.py`:

1. **Teaching audio (core syllables, `voc:*`)** — real-human standard readings
   for the 23 initial call-readings, 96 toned finals, and 64 toned
   whole-syllables, scraped from the pinyin learning page
   `https://123.5ikfc.com/pinyin` (63 base items + the 160-item tone page;
   223 MP3s cached under `./tmp/pinyin_voc/`, decoded to 16 kHz via ffmpeg).
   The ü-row files (ǖǘǚǜ, ǖn…, üē…) exist there directly, so the previous
   homophone workaround is only kept as the TTS fallback path.
   **License note:** scraped educational audio — fine for personal builds;
   redistribute or ship commercially only with permission from the source.
2. **Edge TTS (example-word pool, `edge:*`)** — reading real words is not the
   TTS weak spot, so the 81 word clips stay synthesized but moved to
   Microsoft Edge TTS (neural voice `zh-CN-XiaoxiaoNeural`, fed the hanzi —
   not the pinyin string; `edge-tts` CLI ≥7.3.1, direct WSS is 403 from CN
   exits so the generator retries through `proxychains`). Raw MP3s cached
   under `./tmp/edge_cache/` and not committed. Voice usage is subject to
   Microsoft's neural-voice terms; commercial use should switch to a
   licensed Azure Speech resource.

Shared post-processing: energy VAD silence trim (60 ms pad) → peak
normalization to 0.7 FS → adaptive 5/4/3.2 kHz low-pass → IMA-ADPCM. The
firmware decoder (`main/adpcm_decoder.c`) is bound to the encoder by the
`tests/adpcm_golden.h` fixture; corpus SNR after the final pass:
min 14.6 / mean 24.0 dB.

## Battery profiles

[`battery/wanli-500mah-profile2-xil40x-20261020.txt`](battery/wanli-500mah-profile2-xil40x-20261020.txt)
contains the supplied CW2017 profile for the Wanli New Energy 500 mAh cell
(profile2, XIL40X, 2026-10-20). It is an unchanged copy of the project-supplied
file, retained at the maintainer's request for this firmware update. Its
original filename is recorded in the paired Chinese document. No separate
license was included in the supplied file.

The format is 80 lines of two hexadecimal digits, one byte per line in register
order. The BSP embeds those bytes in `components/bsp/src/bsp_battery.c`; the
host gate checks the source file and initializer for an exact match. Text-file
SHA-256: `7ea96eba4634f4495a37c25ffacd54c1deaa0693b162c892d671a2ba68460919`.
Decoded 80-byte SHA-256:
`fa7365671093ef449c5bdcfb4adb279e3d275f888109f50b6b2f21e9b96220d5`.
This is a fuel-gauge profile, not a charging configuration or a generic profile
for every 500 mAh cell; see the [hardware guide](../docs/hardware-design/AI_HARDWARE_DEVELOPMENT_GUIDE.md#9-cw2017-fuel-gauge).
